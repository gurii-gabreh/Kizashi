# jma-xml-poc

気象庁防災情報XML（JMAXML）から東京都の市区町村単位の警報・注意報発表状況を
抽出するパーサーの技術検証（PoC）。Cloudflare Workersでの本実装を想定し、
Workers上でも動く純JS実装の `fast-xml-parser` を使用している。

## 検証状況

- ✅ **パース処理そのものは検証済み。** `docs/reference/jmaxml_format_v1_3.pdf`
  （気象庁「気象庁防災情報XMLフォーマット」Ver.1.3、2022年12月9日版）の
  1.3.11節に示された記述例（`Information` > `Item` > `Kind`（警報種別・
  `Condition`＝現象種別）/ `Areas` > `Area`（市区町村名・JISコード））をもとに
  組み立てた検証用サンプル（`sample_warning.xml`）で、東京都（JISコード先頭
  "13"）の警報のみを抽出し、`Condition` が「土砂災害」のものを識別できることを
  確認した。
- ⚠️ **実際の配信XMLでの検証は未実施。** このセッションは `xml.kishou.go.jp`
  へのネットワークアクセスが組織ポリシーでブロックされており、実際に気象庁が
  配信しているXMLを取得できなかった。`sample_warning.xml` は実データではなく、
  仕様書の記述例から作成した検証用データである点に注意。
- URL自体は `docs/reference/jma_xml_considerations.pdf`（気象庁「XML形式電文の
  ご利用にあたっての留意事項」）に記載の
  「気象庁防災情報XMLフォーマット情報提供ページ」（http://xml.kishou.go.jp/index.html）
  で確認済み。フィード一覧・実際の配信XMLの取得は、ネットワーク制限のない
  環境（例：実際のCloudflare Workers環境）で改めて検証する必要がある。

## 気象業務法上の重要な確認事項

`docs/reference/jma_xml_considerations.pdf` に、公開XML電文の編集・加工について
明記されている。企画整理.md セクション5・9の「気象庁データは独自予報として
発信せず、公式発表の表示・転載にとどめる」という方針は、この留意事項と一致する。

- **許される例（原文引用）：** 「公開ＸＭＬ電文に含まれる特定地域を対象として、
  その地域に関係する要素・属性のみの情報を選別して切り出し、ひとつの電文として
  再構築する場合。（例：「東京地方23区西部」を切り出し、ひとつの電文として
  再構築）」→ 本アプリが行う「東京都・区市町村単位への絞り込み」はこの許容例に
  合致する。
- **許されない例：** 「個々の要素を利用者側で独自の予報に編集することにより、
  元の公開ＸＭＬ電文の本質が維持されないような編集・加工を行う場合」
  → 警報の値・種別そのものを変更するような処理は行わない。

## 使い方

```bash
npm install
node parse.mjs                    # 同梱のsample_warning.xmlを解析
node parse.mjs path/to/real.xml   # 実際に取得したXMLを解析
```
